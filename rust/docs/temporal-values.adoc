= Temporal dependency migration proposal

Replace chrono and chrono-tz with maintained time, tz-rs and tzdb libraries.
The libraries calculate calendar and timezone rules; the driver retains TypeDB's
civil-value, leap-second, protobuf and display contracts. The parser migration
changes only its private future-builder formatter, leaving the grammar and AST intact.

== Public API

This is a Rust API migration, not an API-compatible patch release. Date becomes
time::Date; Datetime and DatetimeTZ become driver domain types. TimeZone uses
NamedTimeZone or time::UtcOffset. The Chrono-specific Offset adapter is removed.
Use checked constructors and TryFrom<PrimitiveDateTime>. Leap seconds have civil
second 60; wire_parts retains the previous second-59 / extended-nanoseconds wire
representation. local_candidates returns both fold candidates or an empty list
for a gap. from_local_datetime requires a unique candidate. Calendar duration
conversion to std::time::Duration rejects nonzero months and days.

The C ABI and protobuf remain unchanged. Named timezone aliases, fixed-offset
seconds, UTC instant equality, nanosecond precision, pre-epoch timestamps and the
existing datetime year range are retained. Maintained IANA data can include rule
corrections; UTC instants and timezone identifiers are never silently rewritten.

== Integration

The paired TypeDB dependencies proposal adds the maintained libraries to the
canonical Bazel crate registry. Keep shared Chrono registrations for unrelated
server consumers. Once that prerequisite lands, update the normal dependencies
revision. No local path override or JITPOMI runtime fork belongs in the release.

Cargo checks, 12 driver unit tests, C ABI tests and 36 live value tests pass against
TypeDB 3.15.0. Equivalent temporal changes on the existing 3.13 transport pass all
six live DogRS data-layer isolation, policy rollback and uniqueness tests. The
TypeDB 3.15 policy failures were traced to schema-existence queries in DogRS:
fetch projected an impossible type through an inline function. Returning native
type rows with select fixes both empty-subtype and unrelated-attribute checks.
All six live isolation tests now pass on both TypeDB 3.13 and 3.15. Authorization
functions, context binding, write checkpoints and rollback checks remain intact.

Bazel verification now passes for the driver and parser unit targets and the C
shared library. Rust 1.98 includes the LLVM Mach-O LINKEDIT fix; rules_rust 0.75
supports the current toolchain without TypeDB's old patched rules_rust fork.
The canonical TypeDB crate universe ships a cargo-bazel lockfile. Consumer
modules import its exports without duplicating Rust crate identities. The
protocol build-import update is a coordinated prerequisite too.

Removing the temporal dependencies does not clear the official upstream transport's
other audit findings. No advisory exceptions are added.
